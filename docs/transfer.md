# Verified transfer foundation

`media_archive.transfer.execute_transfer(config, operation_id, *, open_source, record_result, progress=None, cancelled=None, locks=None, source_occurrence_id=None, sort_copy=False, verify_existing_only=False)`
executes one planned [journal operation](journal.md). The caller plans the exact destination occurrence, expected SHA-256 and size, and all applicable resource locks; it supplies an opener for the verified source plus its relative path and a callback that writes the corresponding history record. It can pass an active lock group that covers the plan's resources. Imports pass the source occurrence ID so recovery can attribute a published copy to the source actually read. The [import planner](import-planning.md) supplies batch selection and free-space preflight independently of execution.

## Copy and publication

1. Reacquire the plan's locks and verify the registered writable destination. Staging and collection destinations must be on a configured local volume; archive destinations must use the current volume of the planned group. A file cannot occupy a reserved collection directory or one of its ancestors. Parent directories are opened without following links or entering nested mounts.
2. Create a private `.media-archive-transfer-<run-id>` directory beside the destination on the same filesystem. The file inside it is never the destination. Local copies use [rsync](https://rsync.samba.org/ftp/rsync/rsync.1) on a verified open source descriptor. ADB copies use the registered source's existing streaming adapter and compute source SHA-256 on that stream. Both paths preserve source bytes and request the source modification time; timestamp precision depends on the destination filesystem. Cancellation is checked at source hash checkpoints and again before publication. A local rsync process must return or be interrupted before a later callback checkpoint can be reached.
3. Read the part independently from disk and require its SHA-256 and size to match the plan. Synchronize the file before publication. A mismatch or interrupted read cannot publish. Audit and inventory exclude the reserved transfer directories from local scans.
4. Publish new paths with [Linux `renameat2(RENAME_NOREPLACE)`](https://man7.org/linux/man-pages/man2/renameat2.2.html). Workflows that allow the hard-link fallback can atomically create a hard link, synchronize the destination directory, then remove the staged name. For [controlled BACKUP replacement](backup-replacement.md), read the old destination against the immutable intent before atomically replacing its name. Synchronize the destination directory and its ancestors before recording publication, including on recovery.
5. Commit the history callback and the journal's completed state together. A repeated call for a committed operation returns its original attempt and verification IDs.

## Recovery

Call the same API with the same operation ID. If the previous attempt might have published, the executor independently checks the destination before opening the source. A matching file can be committed with fresh evidence. A missing new-copy destination or the unchanged previous file in a replacement intent allows a new transfer. Passing `verify_existing_only=True` requires the planned new bytes to be present. Unexpected contents or an unsafe path require review. Reserved parts from interrupted or failed attempts remain on disk for explicit cleanup.

[SORT](sort.md) uses `sort_copy` to check an existing destination and normalized names before every attempt. It can publish a hard link directly from a verified local working file. It falls back to rsync when a direct link is unsuitable. SORT publishes its copied parts with a non-overwriting rename and handles removal of the old working copy after the verified publication commits.

`TransferConflict` is a `StateError` for an unexpected destination. Source, filesystem and verification failures leave an unfinished or failed attempt, with no successful history record. Configuration failures follow the normal registry checks. Cleanup of failed parts is manual. Direct filesystem edits outside the application do not participate in its resource locks.

[Transfer tests](../tests/test_transfer.py) use temporary directories, real rsync when installed and synthetic volume checks and ADB streams. They cover independent verification, competing destinations, retained parts and process exit immediately before and after publication. Actual NTFS destination and end-to-end import trials are separate.
